# 研究计划（探索阶段）

## 1. 题目

**暂定主题：** 资源受限条件下推理模型的自适应测试时计算

本项目目前是研究型复现与实证探索，尚未确定论文题目或创新主张。文献盘点显示，单纯研究 DEER 置信度阈值校准与风险—成本权衡已与 ICML 2026 的 Conformal Thinking 高度重合；因此它不再作为本项目预设的主研究问题。首先要验证已有方法、梳理其适用边界，再决定是否存在可辩护的后续问题。

## 2. 背景与动机

测试时计算（test-time compute / inference-time scaling）通过多采样、延长推理、搜索或验证来提升语言模型回答质量。固定预算简单但可能浪费：简单题获得过多计算，难题又不够。自适应策略尝试把预算投向更可能从额外推理中获益的题目。

难点在于：

- 模型的低置信度不一定意味着“多算就能变对”；
- 多个答案一致也可能是集体犯错；
- 不同题目之间分配预算，必须在相同总成本下比较；
- token 数、FLOPs 和实际延迟并不等价，尤其小模型的推理可能受访存或硬件影响。

## 3. 研究问题与可证伪假设

### 当前探索问题（不是已确立的研究缺口）

在资源受限的小模型推理设置中，现有自适应早停/预算控制方法能否被可靠复现？模型规模、量化和任务条件会怎样影响其风险—计算权衡？这些条件是否已被相关工作覆盖，仍需逐篇核查。Conformal Thinking 已直接覆盖风险控制式的阈值选择和置信度早停，因此“给 DEER 阈值做风险校准”本身不作为创新主张。

### 子问题

- RQ2：在小模型/受限推理条件下，复现结果与论文报告的趋势有多一致？
- RQ3：模型量化、验证集规模或任务变化对风险控制和成本的影响，现有论文覆盖到什么程度？
- RQ4：哪些失败案例揭示了现有早停信号或评测协议的适用边界？

### 预注册式假设（先记录，看到结果后不追改）

- H1：至少一种公开的自适应推理基线能在记录清晰的受限设置中复现出可解释的准确率—计算权衡；如未复现，应先定位实现、数据或模型差异。
- H2：模型规模、量化或数据条件改变时，方法表现可能变化；具体方向与程度由实验决定。
- H3：误差与成本分析可以识别方法适用边界，但是否构成新贡献取决于与既有工作逐项对照。

H1/H2/H3 是工作假设，不是结论或新颖性声明。

## 4. 候选方法（最小、透明、先当研究假设）

1. 复现并理解 DEER 的推理过程试探答案与置信度早停逻辑，将其作为基线而非预设创新方法。
2. 阅读并对照 Conformal Thinking 的信号、风险定义、阈值选择、有限样本校正、双阈值机制和实验范围。
3. 选择与研究问题相匹配的公开基线；在 test 冻结评估准确率、token 成本、wall-clock time 与风险指标。
4. 分析模型/数据条件变化、难度分组与失败案例；不在 test 上调参。
5. 与普通生成及预算匹配的固定计算基线公平比较。

实现前必须核对：已有论文是否已实现等价策略、采用什么不确定性信号、成本怎么定义。如果候选问题与已有工作重合，应先将其作为复现或对照，不把更换模型、数据或超参数自动视为新贡献；只有在对照文献后确认仍有具体且重要的未回答问题，才设计后续研究。

## 5. 实验设计

### 模型与算力

- 起步选择能在本地设备稳定运行的小型开放权重指令/推理模型；候选型号和量化方案通过显存及速度 smoke test 决定。
- 先不做全量预训练或大规模 SFT/RL。若后续假设确实需要训练，再评估租用 GPU 的时间和成本，不预设必须花钱。
- 记录模型名称、权重版本/哈希、tokenizer、精度/量化、推理库版本、显卡和驱动。

### 任务和数据

- 先从可自动判分的数学/符号推理题开始，保证可以重复评估。
- 选择一个开发集和至少一个独立测试集；注意数据集泄漏/污染、答案解析失败与题目难度偏差。
- 不以一个 benchmark 的单次分数作为结论。最终数据集待文献盘点与运行预算评估后确定。

### 基线

- Greedy / single sample。
- Fixed-N sampling + majority vote（self-consistency）。
- DEER 作者实现的动态早停（首个主复现 baseline）。
- Conformal Thinking 中适用于选定实验范围的风险控制机制（若能可靠复现）；不能仅凭重实现既有机制宣称创新。
- 与近期验证粒度/推理扩展方法的差异化对照：若代码、模型限制导致无法严格复现，必须写明。
- Adaptive pilot + extra-budget 策略。

### 指标

- 主要：accuracy 与平均生成 token 数的 Pareto 曲线；固定总预算下的 accuracy。
- 次要：每题正确率、答案一致率、简单/中等/困难分组表现、推理 wall-clock time。
- 统计：多随机种子或 bootstrap 置信区间；记录失败/无效答案比例。
- 预算：同时报告生成 token 总量和墙钟时间；不能把相同 token 量直接说成相同 FLOPs 或延迟。

## 6. 8–10 周计划与阶段门

### 第 1 周：能力与算力盘点、文献核对

- 读完 `s1`、NeurIPS 2025 的验证粒度论文、Kinetics。
- 填论文矩阵：问题、模型、数据、算法、预算口径、主结论、局限、和本项目重叠点。
- 选本地模型，测能否生成、是否稳定、单题推理时间及显存。
- **阶段门：**若候选问题已被同条件直接回答，记录为复现目标或停止该切口，不进入大规模编码；在定位清楚前不写创新性结论。

### 第 2–3 周：评测和基线

- 固定数据切分、提示词、答案解析器与随机种子。
- 完成 greedy 和固定预算投票基线；先跑小样本验证流程。
- **阶段门：**答案自动判分可靠，成本统计无明显错误，结果可重复。

### 第 4–5 周：复现核心论文基线

- 复现可在当前模型与设备上公平运行的固定预算策略。
- 对齐总 token 预算，报告 accuracy–cost 曲线；说明任何复现偏差。
- **阶段门：**基线趋势能解释；若不能，先查 prompt、解析器、模型版本、采样参数。

### 第 6–7 周：自适应策略与分析

- 实现最小候选策略；阈值只用 validation 选择。
- 做消融：pilot 数量、置信/分歧指标、预算上限。
- 按难度和错误类型分析，重点看“自信但错误”和“多算后变错”。

### 第 8–10 周：稳健性、写作和复试表达

- 至少一个独立任务或模型作外部检查；如果预算不足，优先做不同难度/随机种子的稳健性。
- 写 4–6 页短报告：动机、相关工作、方法、实验、局限。
- 整理复现说明、结果图、失败案例和 8–10 分钟答辩版讲稿。

## 7. 主要风险与应对

| 风险 | 应对 |
|---|---|
| 与已有 adaptive test-time scaling 方法重复 | 先做文献差异矩阵；把贡献定位在新的约束/验证边界，或及时换题 |
| 小模型基准正确率太低，分数噪声大 | 先做小规模模型筛选；减少过难题比例但保留独立测试集；报告区间而非只报点估计 |
| 答案解析器误判 | 对样本人工核查，发布解析器和无效样本统计 |
| 自适应方法利用验证集过拟合 | validation 选阈值，冻结后只评测 test；明确记录调参次数 |
| token 成本下降但 wall-clock 更慢 | 两者同时报告；不混用“计算量”“token 数”“延迟” |
| 8GB 显存/备考时间限制 | 不做大训练；限制模型数与数据规模；每阶段先设停止条件 |

## 8. 项目最终交付

- 可复现的推理评测代码与配置；
- 论文追踪表和逐篇阅读卡；
- accuracy–cost 曲线、置信区间、失败案例；
- 一篇短研究报告和复试展示稿；
- 清楚区分“复现所得”“自己的分析”“待验证猜想”。
