# 实验协议（初版）

这份协议用来防止“预算不公平、看完 test 再调方法、只报告最好一次”的常见问题。正式实验前可以补细节，但开始看 test 结果后不要悄悄改规则。

## 1. 预算公平

- 比较算法时预先规定统一预算单位，初版采用**生成 token 总量/每题平均 token**；如果模型支持可靠 FLOPs 统计，再作为补充。
- 每种方法报告实际生成的 token，不把上限 token 当作实际消耗。
- 测试自适应策略时，主要比较固定的全数据集总预算或固定平均预算；不能只让自适应策略多花 token。
- 额外报告 wall-clock time，但注明硬件、批大小、推理库和并行设置。token 相同不代表延迟相同。

## 2. 数据隔离

- `train`（如有）用于模型训练；本项目初版尽量不训练。
- `validation` 用于选择阈值、提示词与超参数。
- `test` 仅用于冻结配置后的最终评估。
- 记录数据来源、版本、许可证、样本 ID、过滤和去重方法。
- 记录模型/数据可能存在的训练污染风险；无法排除时如实写入局限。

## 3. 运行控制

每个配置固定并记录：模型与 tokenizer 版本、提示模板、采样温度、top-p、随机种子、最大新 token、答案提取方法、环境版本与硬件。

建议至少重复多个随机种子；若算力有限，先用小子集调试，完整 test 上保留至少 3 个种子或用 bootstrap 估计区间。数据子集和排除规则须在结果出来前写下。

## 4. 主要结果

- Accuracy vs 平均生成 token 曲线；
- 固定总 token 预算下的准确率；
- 不同难度桶的准确率和成本；
- 额外计算后由错转对、由对转错、始终错误、始终正确的比例；
- 预算分配信号的校准/预测能力；
- 无法解析答案的比例与抽样人工核验。

报告均值与置信区间，不只报最佳点。若采用多个 benchmark，逐个报告，不能只挑有利数据集。

## 5. 实验决策规则

- 初期只做最小样本 smoke test，确认加载、生成、答案解析、计费统计正常。
- 基线结果异常时先排查环境/解析器/提示词，不急着归因于算法。
- 若自适应算法没有收益，保留结果并分析“为什么”；不在 test 上反复调到显著。
- 任何偏离协议的操作写入实验日志。
